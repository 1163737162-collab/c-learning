# 第 13 章：底层程序设计

先打开 `练习`，按编号自己补全 TODO；遇到卡点再看 `参考答案`。每个文件都是独立的程序，一次只编译一个，不要把所有 `.c` 一起编译。第 08 题是讲义上的思考题。第 11 章指针和第 12 章结构体的现有练习仍在本目录的上一级 `review` 下。

## 练习顺序与自测

1. `01_endian.c`：用字符类型观察内存。常见 Mac 输出 little endian；具体结果取决于机器。
2. `02_shift.c`：10 左移一位为 20，右移一位为 5，原值仍为 10。
3. `03_bitwise.c`：5 和 3 的与、或、异或分别为 1、7、6；取反的十六进制输出取决于 unsigned int 位宽。
4. `04_xor_swap.c`：10、20 交换后为 20、10。实际开发通常用临时变量，更清晰；异或交换不能用于同一个对象。
5. `05_count_ones.c`：10 的二进制是 1010，有 2 个 1；0 有 0 个。把 -1 转成 unsigned int 后，结果的 1 的个数取决于该类型的位宽。
   补充：`05b_count_ones_mask.c` 用掩码逐位检查；`05c_count_ones_division.c` 用除二取余。三种方法各自练习并比较思路。
6. `06_set_clear.c`：13 → 29 → 13。讲义从右往左数第 5 位，对应从 0 开始的下标 4。
7. `07_permissions.c`：最终读和删除开启，写和执行关闭。
8. `08_power_of_two.c`：0 不是 2 的幂；1、8 是；10 不是。

## 对照讲义时注意

- 第 12–13 页写 `num1 = -5`，注释却写“−3 的补码”；二进制过程实际对应 −5。`printf("%d", ...)` 打印的是有符号整数的十进制数值，不是“打印原码”。
- 第 15 页的 `a ^ 0 = 0` 是笔误，正确的是 `a ^ 0 = a`。
- 第 15 页用 `1 << i` 数 1，移到有符号位可能产生未定义行为，且固定 32 位不适合所有实现。第 16 页的有符号 `num - 1` 遇到最小值也会溢出。参考答案用 unsigned 避开这两个问题。
- 左移负的有符号数、或左移导致有符号结果无法表示，属于未定义行为；负的有符号数右移结果是实现定义的。移位次数必须不小于 0 且小于提升后左操作数的位宽；练习优先用 unsigned。
- 讲义第 14 页的加减交换可能发生有符号溢出；参考答案用异或交换演示题意。生产代码通常用临时变量。
- 讲义把补码和 `int` 的 4 字节作为常见机器模型讲解；C11 不保证所有机器如此。参考代码不固定 int 宽度，也不将所有非小端布局都断定为大端。
