## 本章写法说明

- `malloc` 的内存要先写后读；`calloc` 把分配空间的各位清零，本章的 `int` 数组因此初始为0，不把这条规律泛化到所有类型的语义默认值。
- 每次分配都检查失败。`realloc` 使用临时指针，并只请求非零大小；失败时原内存仍有效，成功后使用返回值并重新取得元素地址。扩容后新增区域要初始化，缩容后不可访问已被裁掉的元素。
- 本章使用固定的小元素个数，柔性数组示例另外检查大小运算溢出。若改成外部输入，还须先验证正数范围与总字节数。`malloc(0)` 在C17中有实现定义的处理，本章不依赖它，也不调用 `realloc(p, 0)`。
- `free` 只接收有效分配的起始指针或 `NULL`。释放后置空只改变这一个指针变量，不会自动修复其他别名。错误语句只在注释或辨析文档中出现。
- 字符串输出使用固定格式，如 `printf("%s", str)`；不直接把字符串内容作为格式串。`sizeof` 的结果用 `%zu` 输出。
- 标准柔性数组写作 `int a[]`，在结构体最后，前面有其他具名成员。`int a[0]` 是部分编译器的扩展，不作为可运行示例。`sizeof` 不包含尾随数组的元素空间，但结构体可能有填充，不能把结构体大小写死为4。

## 两种实现比较

| 项目 | 柔性数组成员 `int a[]` | 指针成员 `int *a` |
| --- | --- | --- |
| 示例分配 | `sizeof(结构体) + 元素个数 * sizeof(int)` 一块 | 结构体与元素数组各一块 |
| 示例释放 | 一次 `free(结构体指针)` | 先释放成员数组，再释放结构体 |
| 布局 | 元素跟在结构体后面 | 结构体保存另一个分配块的地址 |
| 扩缩容 | 调整整个分配块，结构体与元素地址可能改变 | 可单独调整元素数组，并更新成员指针 |
| 取舍 | 便于整体管理，可能有利于局部性、减少分配次数 | 成员数组可独立调整，但有额外清理责任 |

连续布局不等于所有程序都必然更快；第06题比较管理方式，不把一次运行当作性能测试。直接赋值含指针的结构体不会深拷贝数组；直接赋值含柔性数组的结构体也不会复制尾随元素，本组练习不进行这种复制。
