# 内存错误辨析

本页是按主题编写的补充练习，不代表原 PDF 的题目、题序或答案。两个 `04_memory_errors.c` 都可以单独编译；练习版默认只输出提示后退出。

## 先记住这条顺序

申请内存 → 判断是否成功 → 在有效范围内初始化和使用 → 释放一次 → 不再使用原内存。

`malloc` 返回的内存没有自动初始化。保存申请起点的 `base` 在本例中负责释放；`cursor` 和 `alias` 只借用它，不能分别再释放同一块内存。这是本例的编程约定，C 语言不会自动替你维护这种关系。

## 错误片段：只辨析，绝对不要运行

以下代码块故意展示错误，**NEVER RUN：不要复制、取消注释或拼成程序运行**。未定义行为不保证立刻报错，也不保证每次表现相同。

### 1. 没有检查申请结果

```c
/* NEVER RUN：错误片段。 */
int *p = malloc(5 * sizeof *p);
p[0] = 10; /* 若 malloc 返回 NULL，这里就不能访问。 */
```

先判断 `p == NULL`。申请失败就报告错误并结束当前操作，不要解引用空指针。申请成功后还必须安排释放。

### 2. 循环边界多走一步

```c
/* NEVER RUN：错误片段；假设 p 指向成功申请的 5 个 int。 */
for (size_t i = 0; i <= 5; ++i) {
    p[i] = 0; /* i == 5 时越界。 */
}
```

5 个元素的下标是 `0` 到 `4`，条件应为 `i < 5`。可以形成 `p + 5` 这个末尾之后的指针，但不能读取或写入 `*(p + 5)`。

### 3. 释放不属于动态分配的对象

```c
/* NEVER RUN：错误片段。 */
int value = 10;
int local[5] = {0};
const char *text = "hello";
free(&value);      /* 自动存储期的局部变量。 */
free(local);       /* 自动存储期的局部数组。 */
free((void *)text); /* 字符串字面量；强制转换不会改变其来源。 */
```

这些对象都不是由动态内存分配函数交给你释放的块。不能因为“有地址”，就把它传给 `free`。

### 4. 释放块内部的地址

```c
/* NEVER RUN：错误片段；假设 base 指向成功申请的 5 个 int。 */
int *cursor = base + 1;
free(cursor); /* 它不是分配函数返回的起点。 */
```

保留 `base`，让 `cursor` 单独移动。清理时调用一次 `free(base)`。如果把唯一的起点指针不断向后移动，还可能失去正确释放所需的地址。

### 5. 重复释放

```c
/* NEVER RUN：错误片段；假设 p 指向一块有效的动态内存。 */
free(p);
free(p); /* 同一块内存已经被释放。 */
```

释放之后执行 `p = NULL`，可以防止以后经由这个变量再次释放旧块。`free(NULL)` 合法且不做任何事情；它不意味着可以对旧地址随意重复调用 `free`。

### 6. 丢失最后一个可释放的指针

```c
/* NEVER RUN：错误片段；假设 malloc 成功且没有其他指针保存起点。 */
int *p = malloc(5 * sizeof *p);
p = NULL; /* 内存还在，但起点已经丢失：内存泄漏。 */
```

把指针清空不等于释放内存。正确顺序是 `free(p)`，再 `p = NULL`。函数提前返回、覆盖原指针等路径，也要检查是否遗漏释放。

### 7. 释放后继续使用，或忘记别名

```c
/* NEVER RUN：错误片段；假设 p 指向有效且已初始化的动态内存。 */
int *alias = p;
free(p);
p = NULL;
printf("%d\n", *alias); /* alias 仍对应已经失效的内存。 */
free(alias);            /* 也不能靠别名再释放一次。 */
```

`p = NULL` 只修改变量 `p`，不会自动改动 `alias`。释放后的别名不能再被用于访问、比较地址、打印旧地址或再次释放。可直接给别名赋 `NULL`；赋值不需要读取它原来的值。参考程序在释放前就将自己掌握的别名清空，使生命周期更容易看清。实际程序还要确保没有其他代码保留并继续使用那些别名。

### 8. 把普通文本当作格式串

```c
/* NEVER RUN：错误片段。 */
const char *text = "%d %s";
printf(text); /* 格式串要求参数，但这里没有提供。 */
```

`printf` 把第一个参数当作格式说明。若文本含 `%`，它可能被当成转换说明，导致参数不匹配等错误。输出普通字符串应使用 `printf("%s", text)`，或使用 `fputs(text, stdout)`；`puts(text)` 还会自动补一个换行。这是格式使用错误，和内存的申请、释放不是同一种问题。

## 对照参考程序检查

| 检查点 | 参考程序的做法 |
| --- | --- |
| 申请失败 | 判断 `base == NULL`，报告后退出 |
| 初始化和边界 | 先赋值，再读取；循环条件都是 `i < count` |
| 释放责任 | `base` 保存起点，只由它释放原块 |
| 游标和别名 | 只在内存有效时使用，释放前设为 `NULL` |
| 清理顺序 | 先释放，再把 `base` 设为 `NULL` |
| 安全输出 | 使用固定格式串 `"%s\n"` |

正常运行参考程序会输出数组 `10 20 30 40 50`、第二个元素 `20` 和文本 `完成度：100%`，然后完成清理。练习版没有申请内存，因此默认没有需要释放的资源；按 TODO 填写时，仍须保留成功分配后的清理路径。
