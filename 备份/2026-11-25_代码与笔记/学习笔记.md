## 2. 地址、数组与指针：今天最重要的一组区别

### 为什么有时参数带 &，有时不带

```c
int n;
char word[100];
scanf("%d", &n);
scanf("%99s", word);
```

- `n` 是整数值；`&n` 才是整数变量地址。
- `word` 在这里自动转换为首字符地址，已经能交给函数使用。
- 字符指针本身保存的也是地址，所以 `strcmp(word, week[i])` 的两个参数都是地址。
- 没有写 `&`，不代表传的不是地址。C 的参数传递仍然是传值，指针参数传过去的是地址这个值的副本。

### 二维数组的 str 和 str[0]

```c
char str[5][100];
char *max = str[0];
```

| 表达式（通常的表达式环境） | 类型 | 指向什么 |
|---|---|---|
| `str` 转换后 | `char (*)[100]` | 第一行数组 |
| `str[0]` 转换后 | `char *` | 第一行的第一个字符 |
| `str + 1` | 指向下一行的指针 | 跨过 100 个字符 |
| `str[0] + 1` | 字符指针 | 跨过 1 个字符 |

两者起始位置相同，不代表类型和加一的步长相同。数组与指针也不是同一种对象：指针变量 `p` 可以 `p++`，数组名不能 `a++`。

### 指针变量可以自增，计算出的地址不能直接自增

今天曾写：

```c
*(t + m - 1)++
```

`(t + m - 1)` 是计算结果，不是可以修改的指针变量。可先移动变量：

```c
t += m - 1;
while ((*s++ = *t++) != '\0')
    ;
```

`*t++` 按 `*(t++)` 理解：读取移动前所指的字符，同时让指针移到下一个字符。`m` 是从 1 开始的字符序号，所以数组偏移为 `m - 1`。

## 3. 字符串比较：比较字符，不是比较数字值

`strcmp(s1, s2)` 从左向右比较，遇到第一个不同的字符就决定大小；字符按 `unsigned char` 的值比较。

| 返回值 | 含义 |
|---|---|
| 小于 0 | s1 较小 |
| 等于 0 | 内容相同 |
| 大于 0 | s1 较大 |

不保证返回值只有 -1、0、1。因此：

```c
if (strcmp(str[i], max) > 0)  // 当前字符串更大
    max = str[i];

if (strcmp(word, week[i]) == 0)  // 内容相同
    position = i + 1;
```

直接写 `if (strcmp(...))` 表示“不相同”：负数也被 if 当作真。

例子：`"peach"` 和 `"pear"` 的前三个字符相同，第四个字符 `c < r`，所以 `"peach"` 更小。`"abc"` 小于 `"abcd"`，因为前者先遇到结束符。

第五题的 `"23"`、`"345"`、`"6789"` 恰好按首字符顺序排列，看上去与数值顺序一致。但字符串 `"9"` 大于 `"100"`，因为 `'9' > '1'`，并没有进行数值转换。

## 4. 输入：输入流里的换行，与数组里的换行

### scanf 后留下的换行

```text
3↵
happy new year↵
```

`scanf("%d", &repeat)` 读走数字 3，后面的换行仍留在输入流中。接下来的 `fgets` 会立即读到它，数组变成 `"\n"`。

按样例这种“数字后直接换行”的输入，可以在读取 repeat、m 或单个字符 c 后，用 `getchar()` 读走换行。若数字后还可能有空格，一个 `getchar()` 不够稳妥，可以清理到行末：

```c
int ch;
while ((ch = getchar()) != '\n' && ch != EOF)
    ;
```

不要随意使用带尾随空白的 `scanf("%d\n", ...)` 代替：格式里的空白会继续跳过空白，交互输入时可能等待后续非空白字符。

### fgets 自动补结束符，但保留读到的换行

```c
fgets(t, sizeof t, stdin);
```

成功读取时，最多读取容量减一的字符；遇到换行或输入结束也会停止，并补 `\0`。若读到了换行，该换行也存入数组。

输入 new 再按回车：

```text
'n' 'e' 'w' '\n' '\0'
```

此时 `strlen(t)` 为 4。去掉换行后才是 3：

```c
t[strcspn(t, "\n")] = '\0';
```

`strcspn` 返回第一个换行符的位置；如果没有换行，返回字符串长度，这时给原结束符位置再赋 `\0` 仍然安全。也可自己循环找：

```c
for (int j = 0; t[j] != '\0'; j++)
{
    if (t[j] == '\n')
    {
        t[j] = '\0';
        break;
    }
}
```

### 不用 fgets：scanf 的扫描集合

```c
scanf("%999[^\n]", t);
getchar();
```

`[^\n]` 表示读取不是换行的字符，所以空格也可以读入。`999` 是最大读取字符数，给 `t[1000]` 留一个结束符位置。这个转换不读取换行，且不匹配空行；使用时要检查读取结果，并保证之前的换行已经处理。

### 不用 fgets：逐字符循环读取

```c
char t[1000];
int ch, j = 0;
while ((ch = getchar()) != '\n' && ch != EOF)
{
    if (j < 999)
        t[j++] = ch;
}
t[j] = '\0';
```

字母和空格都保存；换行读走但不保存；最后自己补字符串结束符。`ch` 用 int，才能同时容纳字符值和 EOF。超过容量的字符会被继续读走但不保存，避免下一次输入从上一行中间开始。

### 字符串到底开多大

第 11 题没有明确长度上限。`char t[1000], s[1000];` 是暂定容量，不是题目保证。目标后缀不会比原字符串长，因此 s 和 t 可以开同样大小。只定义 `char *t;` 没有提供可写的字符存储空间，不能直接读入。

## 6. 第12题：为什么 10/10 仍有输入问题

已核对：2026-11-25 19:12:46 的提交显示答案正确 10/10，页面展示 1 个测试点。提交代码与归档代码一样，`scanf("%c", &c)` 后没有读走换行。

隐藏输入不可见，不能断定后台只测了 repeat=1。已能确认的是：满分测试没有暴露这个多组输入问题。

实际用原代码运行：

```text
2
bee
e
cat
a
```

应输出：

```text
result: b
result: ct
```

原代码实际输出：

```text
result: b
result:
```

第二行后缀为空；实际输出在冒号后还有一个空格，原始输出字节见 `验证记录.json`。

原因按顺序看：

1. 第一组 fgets 读取 `bee\n`，数组中换行被替换为 `\0`。
2. scanf 只读走 e，输入流中还留着这一行的换行。
3. 第二轮 fgets 立即读到该换行，str 变成 `"\n"`。
4. 去换行后变成空字符串；随后的 `%c` 又错把下一组 cat 的 c 当成删除字符。

按样例每个字符后直接换行的格式，可在读完 c 后补 `getchar()`。更一般的输入可清理到行末。**本次仅归档与说明，没有修改网页或原源码。**

### 斐波那契：先把下标定义看清楚

题目从 0 开始：F(0)=0、F(1)=1、F(2)=1、F(8)=21。早期把 F(1) 写成 0，整段偏了一位，输入 0 还会无限递归。题目要求循环，不能只把递归边界改对就结束。

普通循环在正式提交时拿到 8/10，最后一点超时；只在浮点溢出后停止仍为 8/10。最后使用 static 数组保存已经算过的项，避免重复调用时从头计算，五个测试点全部通过。

static 的作用：函数返回后仍保留数组和已经计算的位置。下一次请求已经算过的下标，直接取值；未算过的部分继续循环推进。

`isfinite` 判断浮点数是不是有限值。通常的 IEEE 754 double 中，F(1476) 仍有限，F(1477) 溢出为正无穷，因此缓存开 1478 个位置可包含下标 0 到 1477。这个大小与 double 的表示范围相关，不是随便估出来的字符串容量。

### 统计数字：0 和负数都要覆盖

用 do-while，确保 number 为 0 时也检查一次。负数每次取余可能得到负的一位数，给这一位取相反数即可；不要直接对整个最小 int 取负数，以免溢出。

### 字符串连接：先找末尾，再复制

先移动 s1 到原来的 `\0`，再从 s2 开始复制，连 `\0` 一起覆盖过去。没有调用字符串处理库函数，符合这题要求。
